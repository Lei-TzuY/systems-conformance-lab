# Command target configuration contract

`CommandTarget` is the immutable execution boundary used by `DifferentialHarness` and by replay-context fingerprinting. Its `argv` elements and explicit environment keys and values must already be strings. The constructor rejects text/bytes passed as the argv container itself and rejects non-string argv or environment members with `TypeError`; it does not coerce arbitrary Python objects with `str(...)`.

This matches the fail-closed contract enforced by `run_process()`. Rejecting invalid configuration before it becomes a `CommandTarget` prevents a caller object from being silently transformed into different process arguments or environment values and then fingerprinted as though that transformed configuration had been supplied intentionally.

Caller-owned argv and explicit-environment containers are consumed exactly once into local immutable snapshots, and those snapshots are what get validated, stored, fingerprinted, and ultimately executed. Validation never performs one traversal and then trusts a second traversal of the caller container. This matters for mutable containers, custom `Sequence`/`Mapping` implementations, and concurrent callers: a changing source cannot make the validated values differ from the values that enter replay identity or process launch.

`env=None` continues to mean inherited environment, while an explicit mapping is sorted into deterministic key order after the single snapshot is validated. Validated targets continue through the normal real-process runner, including timeout, byte-budget, process-tree cleanup, and infrastructure-failure classification. The shared runner applies the same single-snapshot rule at its direct API boundary so callers that bypass `CommandTarget` receive the same fail-closed execution semantics.
